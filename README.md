# Инструкция по запуску проекта

## 1. Требования

Для работы проекта необходимы:

- PHP 8.5 или совместимая версия;
- Composer;
- Laravel 13;
- SQLite;
- Node.js и npm (если используются frontend-зависимости).

## 2. Установка зависимостей

Клонировать проект и перейти в его директорию:

```bash
git clone <repository-url>
cd my-app-darya
```

Установить PHP-зависимости:

```bash
composer install
```

Установить frontend-зависимости:

```bash
npm install
```

Создать файл конфигурации:

```bash
cp .env.example .env
```

Сгенерировать ключ приложения:

```bash
php artisan key:generate
```

## 3. Настройка базы данных

В файле `.env` указать:

```env
DB_CONNECTION=sqlite
```

Создать файл базы данных, если он отсутствует:

```bash
touch database/database.sqlite
```

Выполнить миграции:

```bash
php artisan migrate
```

Для заполнения базы тестовыми данными:

```bash
php artisan db:seed
```

## 4. Запуск приложения

Запустить локальный сервер Laravel:

```bash
php artisan serve
```

По умолчанию приложение будет доступно по адресу:

```text
http://127.0.0.1:8000
```

Для запуска frontend-сборки в режиме разработки:

```bash
npm run dev
```

## 5. Настройка электронной почты

В проекте используется SMTP-сервер Gmail.

Пример конфигурации `.env`:

```env
MAIL_MAILER=smtp
MAIL_SCHEME=smtp
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=your_email@gmail.com
MAIL_PASSWORD=your_app_password
MAIL_TIMEOUT=30
MAIL_FROM_ADDRESS=your_email@gmail.com
MAIL_FROM_NAME="${APP_NAME}"
```

**Важно:** для Gmail необходимо использовать пароль приложения, а не обычный пароль от аккаунта Google.

Не публикуйте файл `.env` и не добавляйте реальные пароли в Git.

## 6. Работа с очередями Laravel

В проекте используется драйвер очередей `database`. Он позволяет сохранять задания в таблице `jobs` и выполнять их асинхронно.

В `.env` должна быть установлена настройка:

```env
QUEUE_CONNECTION=database
```

Создание таблиц очереди (при необходимости):

```bash
php artisan make:queue-table
php artisan migrate
```

### Запуск обработчика очереди

Для обработки заданий необходимо запустить отдельный процесс:

```bash
php artisan queue:work --timeout=120 --tries=3
```

**Важно:** обработчик должен постоянно работать в отдельном окне терминала. Если он остановлен, новые задания будут накапливаться в таблице `jobs`, но не выполняться.

### Проверка очереди

Открыть Tinker:

```bash
php artisan tinker
```

Количество ожидающих заданий:

```php
DB::table('jobs')->count();
```

Количество неудачных заданий:

```php
DB::table('failed_jobs')->count();
```

Выход из Tinker:

```php
exit
```

Просмотр неудачных заданий:

```bash
php artisan queue:failed
```

Повторная обработка неудачного задания:

```bash
php artisan queue:retry all
```

### Очистка очереди

Удалить все ожидающие задания:

```bash
php artisan queue:clear
```

Удалить записи о неудачных заданиях:

```bash
php artisan queue:flush
```

**Внимание:** эти команды удаляют задания и записи об ошибках. Использовать их следует осознанно.

## 7. Фоновый запуск Queue Worker на macOS

Чтобы не держать отдельное окно терминала открытым, можно запустить обработчик в фоновом режиме:

```bash
nohup php artisan queue:work --timeout=120 --tries=3 > storage/logs/queue-worker.log 2>&1 &
```

Посмотреть процессы:

```bash
ps aux | grep "queue:work"
```

Посмотреть журнал работы:

```bash
tail -f storage/logs/queue-worker.log
```

Остановить обработчик:

```bash
pkill -f "artisan queue:work"
```

Для постоянной работы в производственной среде рекомендуется использовать менеджер процессов, например Supervisor.

## 8. Полезные команды Artisan

| Команда                            | Назначение                                 |
| ---------------------------------- | ------------------------------------------ |
| `php artisan serve`                | Запуск сервера                             |
| `php artisan migrate`              | Выполнение миграций                        |
| `php artisan migrate:status`       | Проверка миграций                          |
| `php artisan migrate:fresh --seed` | Полное пересоздание БД с тестовыми данными |
| `php artisan route:list`           | Просмотр маршрутов                         |
| `php artisan cache:clear`          | Очистка кэша                               |
| `php artisan config:clear`         | Очистка конфигурационного кэша             |
| `php artisan view:clear`           | Очистка кэша представлений                 |
| `php artisan queue:work`           | Запуск обработчика очереди                 |
| `php artisan queue:restart`        | Корректный перезапуск Worker               |
| `php artisan tinker`               | Интерактивная консоль Laravel              |

## 9. Основные возможности проекта

В проекте реализованы:

- Регистрация и аутентификация пользователей.
- Система ролей `moderator` и `reader`.
- Разграничение доступа с использованием Policies и Gates.
- CRUD-операции для новостей.
- Пагинация списка новостей.
- Добавление и удаление комментариев.
- Премодерация комментариев.
- Отправка уведомлений по электронной почте.
- Асинхронная отправка уведомлений с использованием Laravel Queue и database-драйвера.

## 10. Принцип работы уведомлений

При создании новой статьи:

1. Статья сохраняется в базе данных.
2. Создаётся задание `VeryLongJob`.
3. Задание помещается в таблицу `jobs`.
4. Queue Worker получает задание.
5. Job находит пользователей с ролью `moderator`.
6. Каждому модератору отправляется письмо с информацией о новой статье.
7. После успешного выполнения задание удаляется из таблицы `jobs`.

Таким образом, отправка электронной почты не блокирует основной HTTP-запрос создания статьи.

## Быстрый запуск проекта

После первоначальной установки достаточно выполнить:

**Терминал №1 — Laravel:**

```bash
php artisan serve
```

**Терминал №2 — Queue Worker:**

```bash
php artisan queue:work --timeout=120 --tries=3
```

**Терминал №3 — Frontend (при необходимости):**

```bash
npm run dev
```
